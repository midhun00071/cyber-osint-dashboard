# C10 consolidated production security audit

## Acceptance contract

- Official tasks: B10-01 through B10-07, consolidated as C10.
- Repository checkpoint: `dev` at `c9fcb52b53358015c825dbb4a000aea3b831bc21`; refreshed `origin/dev` matched with divergence `0 0`; the initial tree and index were clean.
- Goal: audit the complete tracked security-relevant application, remediate demonstrated C10 Blocker and Must Fix findings within the existing architecture, add bounded regression evidence, produce the five required evidence documents and two generated CycloneDX SBOMs, and leave every change unstaged and uncommitted.
- Components inspected: root/environment templates, backend application and tests, ORM and committed migrations, frontend source and tests, source policies and every outbound HTTP implementation, orchestration and persistence, production scripts, Dockerfiles, Compose, Caddy, monitoring configuration, dependency manifests, and security documentation.
- In scope: OWASP Top 10:2025, OWASP API Security Top 10:2023, applicable ASVS 5.0.0 requirements, injection, browser and URL safety, API authorization and bounds, SSRF/outbound consumption, logic and transaction integrity, dependencies, SBOMs, containers, configuration, logs, and tracked/history secret scanning.
- Out of scope: live OSINT traffic, third-party DAST, exploit execution, C10-08/C11 load and release work, staging UAT, external alert delivery, off-host backup activation, source activation, schema changes, and edits to committed migrations.
- Security and integrity requirements: fail closed; sanitize errors and logs; preserve backend authorization, CSRF, transaction, idempotency, checkpoint-after-commit, fixed-destination, disabled-source, and UAE approval gates; do not inspect ignored real `.env` files.
- Required tests: bounded C10 backend/frontend security suites plus directly affected existing tests; full backend/frontend regression; type-check/build; Alembic heads/history; Compose validation; dependency, SBOM, secret, and local-image checks.
- Documentation: this report plus `c10-owasp-asvs-matrix.md`, `c10-api-security-inventory.md`, `c10-outbound-security-matrix.md`, `c10-supply-chain-evidence.md`, and `security/sbom/README.md`.
- Definition of done: every frozen Blocker/Must Fix is resolved or precisely blocked with evidence; required generated SBOMs validate; tests and scans are reported honestly; every changed file is reread; migrations remain byte-identical; Git remains at the checkpoint with nothing staged and no commit/push.
- Accepted limitations at freeze: process-local rate limiting; production Next.js currently requires inline script/style execution under the deployed static CSP unless verified build evidence proves otherwise; no claim of blanket OWASP/ASVS compliance; environment-dependent PostgreSQL and external staging checks remain separate gates.

## Methodology and audit universe

The audit used complete tracked-file inventory (568 tracked files), targeted required sink searches over the full production and test trees, complete review of security-critical implementations, imported FastAPI OpenAPI generation, negative-path test review, npm and Python dependency tooling, tracked-only and Git-history secret scanning, and local-image scanning. Raw text matches were traced before classification. No live source request or public-target test was made.

The imported application contained 42 documented OpenAPI paths and 43 documented operations. The private `/internal/metrics` route is deliberately excluded from OpenAPI and rejected at the edge. Default FastAPI documentation routes remain backend-internal because Caddy exposes only `/api/*` to the backend.

## Outcomes, remediation, validation, and sign-off

The frozen remediation set is complete. No demonstrated C10 Blocker or Must Fix remains.

- B10-01 OWASP/ASVS: `c10-owasp-asvs-matrix.md` records all 20 OWASP/API categories plus 30 applicable ASVS 5.0.0 requirements (30 PASS, 0 FAIL) and two technology N/A entries. This is not a certification claim.
- B10-02 injection: ORM/expression-built queries, static trusted migration/provisioning SQL, explicit subprocess argv, fixed headers/filenames, formula-neutralized CSV, plain-text bounded PDF, and sanitized errors passed focused/full regression.
- B10-03 browser: C10-F-002 is resolved; React hostile text remains escaped. Next 16.3.0 build and actual Caddyfile validation passed. CSP inline allowances are retained only with the measured build evidence above.
- B10-04 API: 42 documented paths/43 operations, one private metrics route, and four internal documentation routes are inventoried. Backend roles, BOLA/BFLA, mass assignment, CSRF/content type, exact methods/query names, and byte/message body ceilings passed after C10-F-009.
- B10-05 outbound: all 11 HTTP clients are inventoried; C10-F-003/F-004/F-008 are resolved. Fixed feed redirects now fail closed without `Location` inspection or a second request; proxy isolation, timeouts, decompressed byte/record/page bounds, representation validation, and sanitized errors were verified without live source traffic.
- B10-06 logic: no production mock/fallback/fake-success or assertion weakening was demonstrated. Transaction rollback, checkpoint-after-commit, idempotency, truthful source states, and audit failure paths passed.
- B10-07 supply chain: C10-F-001/F-006/F-007/F-010 are resolved. Production pip/npm audits are clean, formal CycloneDX 1.6 SBOMs validate, current snapshot/history secret scans are classified, and the Caddy derivative now uses only digest/exact-version build inputs.
