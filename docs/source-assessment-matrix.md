## Purpose

This document began as planning documentation for multi-vendor cybersecurity intelligence expansion and now retains superseded commercial rows as historical evidence. It does not authorize future integration, credentials, collectors, APIs, or scheduler behavior.

The repository retains two Censys publication sources with bounded manual live metadata collection, which remain distinct from Platform/API functionality. Censys Platform/exposure, VirusTotal premium/business, Recorded Future, paid credentials, subscription mocks, and commercial free-tier workarounds are retired rather than pending or unapproved future work. Other unrelated source proposals require a separately frozen task.

## Decision Values

| Decision | Meaning |
|---|---|
| `implement_now` | Records implemented bounded public-publication collectors, currently the two Censys families, Anomali Cyber Watch, and the P9-05 Google TI/Mandiant families; it does not approve additional integrations. |
| `future_api` | Candidate for future authorized structured API or standards-based integration after access, licensing, terms, and security review. |
| `manual_catalogue` | Suitable for manually curated metadata or analyst reference records where automatic ingestion is not appropriate or not yet verified. |
| `developer_reference_only` | Useful for architecture, API, protocol, or integration design, but not an intelligence feed. |
| `exclude` | Out of project scope or unsafe for this dashboard. |

## Vendor-Specific Notes

### Censys

- The dashboard must not perform active scanning.
- The dashboard must not trigger Censys rescans.
- Structured Censys Platform/API use is retired by C05 and has no later approval or implementation path in the current plan.
- Exposure intelligence is conceptually enrichment for existing indicators or approved defensive assets, not a reason to probe arbitrary targets.
- Clean canonical URLs must be used if Censys publication links are catalogued; tracking parameters such as `utm_*`, `gclid`, and ad campaign parameters must not be stored.

### Anomali

- The bounded Cyber Watch live collector is manual-only, accepts no arbitrary
  URL, does not parse article-body prose, and retains publication metadata only.
  It rejects selected title, summary, author, and category metadata containing
  IOC-like URLs, IP addresses, domains, hashes, internationalized domains, or
  common defanged forms before adapter invocation.
- The local workflow accepts a reviewed, operator-prepared seven-field catalogue.
  Its adapter is not a comprehensive automatic IOC detector; operators and
  reviewers must exclude article-body text, IOCs and observables, indicator
  hashes/IP addresses/domains, raw HTML, HTTP headers and cookies, attachments,
  media, PDFs, downloads, and malware samples. The verified five-record
  catalogue was reviewed and contained safe metadata.
- During controlled validation on 19 July 2026, the fixed discovery page
  returned HTML with no deterministic main-content region and no approved Cyber
  Watch article links. Discovery failed safely before an article request was
  issued and before database-session creation, and no live records were
  persisted. The request was not rejected with HTTP 403; the observed response
  status was HTTP 200. The reviewed local JSON fallback remains the currently
  operational method.
- STAXX must not become a project dependency because it is unsupported.
- A future generic STIX/TAXII importer is preferred over an Anomali-specific STIX parser.
- ThreatStream, feeds, and TAXII access require current access/licensing verification before implementation.

### VirusTotal / Google Threat Intelligence

- Malware sample downloading is excluded.
- Automated malware submission is excluded.
- Automatic file uploading is excluded.
- Malware detonation features are excluded.
- API integration requires current licensing/access review.
- URL, file, domain, IP, graph, and relationship enrichment must be bounded to existing approved indicators and must not become arbitrary target probing.

### Recorded Future

- Web scraping and automated website harvesting are excluded.
- Future structured integration must use properly authorized programmatic access only.
- Commercial/API access requires current verification before implementation.
- Public research ingestion, if approved later, should use a common publication pipeline and must not infer rights to redistribute report text or indicators.

### Mandiant / Google Security

- Public publication ingestion and structured Google Threat Intelligence API integration are separate integration families.
- Public research can be considered for approved publication metadata ingestion.
- Structured actor, campaign, malware, IOC, relationship, vulnerability, and TTP data require current access/licensing verification.
- Attribution and campaign statements must be represented as source-attributed intelligence, not project-confirmed fact.

### IBM X-Force

- P9-07 implements only operator-supplied local JSON metadata for exact `www.ibm.com/think/x-force/<lower-kebab-slug>` research URLs and exact `exchange.xforce.ibmcloud.com/osint/guid%3A<32hex>` advisory URLs.
- P9-07 performs no IBM network request, scraping, IBMid or guest-access automation, API access, IOC extraction, report/PDF processing, media download, or STIX/TAXII integration.
- API access must be verified before implementation.
- Do not assume legacy or freemium API access.
- Public research and structured X-Force intelligence are separate integration families.
- Reputation and indicator enrichment must not become arbitrary target probing or arbitrary URL ingestion.

## Cross-Vendor Overlap and Canonical Source Ownership

Google Threat Intelligence combines multiple intelligence foundations, including
Google visibility, Mandiant human-curated threat intelligence, and VirusTotal
observable intelligence. For this project, any future capability must map to one
canonical project source definition before implementation.

Conceptual ownership split:

- VirusTotal / GTI observable intelligence: file intelligence, URL
  intelligence, domain intelligence, IP intelligence, community/reputation
  concepts, observable graph relationships, IOC Collections, and IOC Stream /
  threat feeds.
- Google TI / Mandiant threat knowledge: public GTI/Mandiant threat research,
  reports, threat actors, campaigns, malware and tools, vulnerabilities,
  ATT&CK/TTP relationships, and structured GTI threat-object API integration.

Future deduplication and ownership rules:

- use one canonical source definition per provider capability;
- preserve provider object identifiers where licensing permits;
- use publication canonical URLs as part of duplicate prevention;
- do not represent the same provider capability with separate overlapping
  collectors;
- do not create duplicate future implementations solely because Google Threat
  Intelligence combines VirusTotal and Mandiant intelligence.

Threat Profiles are not a canonical ingestion entity for this roadmap. They may
inform future analyst filtering or monitoring design, but they must not be
modeled as ThreatActor, Campaign, Malware, or provider-owned entity profile
records.
